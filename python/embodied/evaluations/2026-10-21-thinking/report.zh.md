# DeepSeek Thinking 诊断：固定 RoboDojo 输入

[English](report.md) | 中文

## 结论

在这些固定输入上，Thinking 提高了原生提示词下的计划准入率，但没有证明物理任务成功率提升。增强在线提示词在本样本中已接纳全部非思考响应。Thinking 暴露了历史/当前 RGB 状态混淆；独立分配的澄清对照消除了已观察到的失败。基础追平和复杂任务优效仍未通过正式验收。

## 固定对照

首批包含此前开发证据中的全部 13 个提供方请求：八个原生格式请求和五个在线初始/恢复请求。推理前复制完整消息列表、图像 data URL 及历史轮次。五次重复、两种 token 上限及两种 Thinking 设置，共 260 个指定调用。用种子 20261021 随机化配对内组顺序及配对顺序，两个工作线程各自在配对内顺序执行。两组统一使用官方端点、`deepseek-flash`、JSON-object 输出及非流式传输，不重试。Thinking 显式关闭，或以 `high` 强度开启。两组保留 temperature 0，但提供方在思考模式下忽略该参数，因此这是可部署配置的对照，并非有效采样控制完全相同。参见[官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

所有调用均返回 HTTP 200 和完整用量，260 个响应报告相同模型和系统指纹。两个响应以 `length` 结束，其余均为 `stop`。这些快照的重复不是独立物理场景：原始 episode 共用一个已知 pickup 布局。判定器检查已注册能力选择、字段类型及按阶段的 bind/restart 决策，不从计划或理由推断物理任务成功。

| 输出上限 | Thinking | 匹配计划 / 指定调用 | API 秒数中位数 | API 秒数 p95 | 截断 |
|---:|---|---:|---:|---:|---:|
| 2,048 | 关闭 | 46 / 65 | 2.03 | 2.67 | 0 |
| 2,048 | High | 61 / 65 | 4.15 | 10.59 | 2 |
| 8,192 | 关闭 | 50 / 65 | 2.03 | 3.04 | 0 |
| 8,192 | High | 63 / 65 | 4.11 | 9.51 | 0 |

在 8,192 上限下，原生格式提示词关闭时为 25/40，high 时为 39/40；在线提示词关闭时为 25/25，high 时为 24/25。因此不能将汇总收益归因于在线恢复能力更强。总生成 token 为关闭时 11,321、high 时 39,490，其中 high 包含 31,852 个推理 token。这些是 API 时延和 token 计量，不是机器人完成时间或账单。

## 已观察到的失败机制

非思考原生格式响应反复将 operations 写成自行构造的对象和参数，而非已注册 ID 字符串。Thinking 减少了此类失败，但不保证准入：一个 high 响应额外添加了顶层 `type` 字段。JSON-object 输出保证 JSON 语法，不保证原生字段集合。

在一个在线恢复输入上，high 响应有时将此前 `observation_lost` 事件的 `rgb_available=false` 当成当前相机状态，尽管最后一条用户消息已附新图像，因而中止并返回空 operation 列表。两组当前场景相同；这是观测时间语义的决策错误，不是当前实际没有 RGB 的证据。在 2,048 上限下，两个 high 调用将输出额度全部用于推理，没有返回最终计划。

## 独立澄清对照

第二批冻结五个在线快照，将原始/澄清提示词与 Thinking 关闭/high 交叉对照。每个条件每快照重复五次，上限为 8,192，不重试，共 100 个指定调用，使用种子 20261022 随机化。澄清增加历史/当前观测时间说明，以及仅从所提供观测计算的当前相机状态。历史轮次、领域上下文和图像字节保持不变。不引入新物理场景或保留评测 case。

| 提示词 | Thinking | 匹配计划 / 指定调用 | API 秒数中位数 | API 秒数 p95 |
|---|---|---:|---:|---:|
| 原始 | 关闭 | 25 / 25 | 1.86 | 2.58 |
| 原始 | High | 22 / 25 | 3.05 | 8.70 |
| 澄清 | 关闭 | 25 / 25 | 1.93 | 2.41 |
| 澄清 | High | 25 / 25 | 2.98 | 4.04 |

所有调用均返回完整响应和用量，指纹与首批一致。原始/high 的三次失败均误读历史 RGB 缺失，澄清/high 的 25 个请求中未出现该错误。这支持组合使用时间说明与状态澄清改善这些快照；不能分别确定文字与显式状态的贡献，也不能证明普遍可靠或仿真成功率提升。

## 真实开发验证

随后一批仿真在所有组统一使用 Thinking high、上限 8,192：原生 N、兼容 H0 和在线 H1。在同一已探索的 pickup 布局上运行九个指定 episode，覆盖正常执行、保持前四次指令以及第三次动作后缺失一次 RGB。[审计结果](live-development.json)保留两个未成功的 episode。全部 11 个提供方请求均完成并返回用量，指纹与固定输入批次相同；三条 H1 链路均通过停止/观测/提交/动作审计。

| 条件 | N 成功 / 原生秒数 | H0 成功 / 原生秒数 | H1 成功 / 原生秒数 |
|---|---|---|---|
| 正常 | 是 / 43.79 | 是 / 42.48 | 是 / 43.43 |
| 保持四次指令 | 是 / 41.40 | 是 / 42.37 | 是 / 78.57 |
| 一次 RGB 观测缺失 | 否 / 无终止记录 | 否 / 无终止记录 | 是 / 77.00 |

原生秒数包含技能冷启动，以首次既有原生终止检查为结束，排除收尾。缺少终止检查不产生完成时间。H1 在每个受扰 episode 中各替换一次；正常 episode 只有一次初始请求。短暂停滞时原生控制器已能恢复，H1 的额外重规划增加了时延，没有提高成功率，因此性能验收前需要校准检测器。RGB 恢复证明在这一个开发 case 上存在可执行收益，不能证明总体成功率提高、L 类任务通过，或与提示词修正分离的 Thinking 效应。

此前另一批 high 对照因 Vulkan 初始化失败而中断，发生在任何提供方请求之前。失败和未完成分配均保留在原始归档。已完成批次单独记录 EGL Vulkan 配置；两批不合并。这些均为开发结果，正式保留集运行数为零，完整原生目录尚未取得可运行资格。

## 集成与验收

在线规划现在标明当前相机可用性，并拒绝序列不新于触发事件的恢复观测。开发转发器可以对 N/H0/H1 统一冻结 `off`、`low`、`high` 或 `max`。执行器单独记录首次既有原生终止检查，不增加环境查询，并排除收尾时间。无密钥 profile 回放检查实际 high 强度线协议字段和保留的 Session 历史。

独立的零推理原生完整目录构造探测因策略环境缺少 `openpi` 而失败。按已下载 OpenPI 清单完整安装时，还发现训练依赖冲突：LeRobot 要求的 rerun-sdk 版本需要 NumPy 2，而清单限制 NumPy 小于 2。因此 checkpoint 目录存在尚不能证明最强原生基线可运行。隔离推理环境和真实仿真验证仍是前置条件，此外还需多子目标执行、可观测抓取/目标事件、独立 L/U/X 评分、消融及预登记保留集统计。[验收要求](../../../../.agents/notes/proposed/architecture/2026-10-20-physicalrsi-phase-one-integration.zh.md)保持不变。
