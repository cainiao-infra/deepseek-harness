# RoboDojo 效果验收记录：2026-10-21

[English](report.md) | 中文

## 摘要

**结论：证据不足，未通过正式效果验收。** 十二次开发 episode、十三次真实 DeepSeek 请求确认了一个视觉缺失恢复场景的局部收益，尚未证明基础任务非劣或复杂任务优效。正式保留集运行数为零。

验收要求仍以[融合设计](../../../../.agents/notes/proposed/architecture/2026-10-20-physicalrsi-phase-one-integration.zh.md)为准。本记录保留规划失败、skill 异常和 GPU 初始化故障；单独登记的诊断三组不替换原批次。

## 条件与范围

全部 episode 使用 `general_pickup`、布局 0、seed 0、`arx_x5`、单环境及既有 `skills.general-pickup.json` 代码策略预设。N 调用原生 API planner，H0 经 DSH 调用并保留原生执行，H1 增加观测事件恢复。N 只是该预设的候选参照，尚未完成 T0 所要求的最强原生配置选择。完整目录有 24 个 skill，包括两种 checkpoint 策略；online v1 加载该目录时在推理前确定性拒绝，预留调用数为零。109 个声明代码文件的摘要均匹配。

开发机使用 NVIDIA RTX PRO 5000 72GB Blackwell、驱动 580.126.09、Python 3.11.17 及隔离的 Node 24.22.0 部署。各组均经官方端点请求 `deepseek-flash`，关闭 thinking，temperature 为 0，使用 JSON-object 响应及 2,048 输出 token 上限。共同 episode 上限为 900 秒及三次实际提供方请求；无效模型输出仍计调用。各 episode 使用独立账本，此前耗尽的六次调用账本不变。

所有 case 都是同一已知布局的开发数据，每条件每组一次运行，不是十二个独立场景。组顺序由各自存档规格固定，尚非正式随机化设计。已检查的 N/H0 初始机器人状态相同；重置后的渲染像素不同，各组均保留了自己的原始传感像素。路由及提示词不接收扰动注入标签。

## 原批次

扰动分别将最初四次关节命令保持在实测位置，或在第 3 次动作后移除一次全部 RGB。每个预分配组均保留在分母。

| 条件 | 组别 | 记录结果 | 动作数 | 调用数 | 评测函数秒数 |
|---|---|---|---:|---:|---:|
| 正常 | N | 成功，原生评分 100 | 110 | 1 | 39.47 |
| 正常 | H0 | 无效计划，未执行动作 | 0 | 1 | 3.74 |
| 正常 | H1 | 成功，原生评分 100 | 110 | 1 | 57.15 |
| 停滞 | N | 成功，原生评分 100 | 110 | 1 | 42.28 |
| 停滞 | H0 | 成功，原生评分 100 | 110 | 1 | 39.36 |
| 停滞 | H1 | 成功，原生评分 100 | 114 | 2 | 90.99 |
| RGB 缺失 | N | skill 异常，无最终成功 | 3 | 1 | 23.80 |
| RGB 缺失 | H0 | skill 异常，无最终成功 | 3 | 1 | 25.02 |
| RGB 缺失 | H1 | GPU 初始化故障，未进入任务 | — | 0 | — |

H0 正常任务的响应将 operation 写成附带自拟参数的对象，而非已注册 ID 字符串，因而被拒绝。停滞条件下三组都成功；H1 替换执行并增加一次模型调用，本 case 没有成功率收益。H1 视觉组的 GPU 故障保留为未成功，没有静默重跑。

## 单列的视觉诊断

该完整三组在 GPU 故障留证后单独登记，沿用相同执行版本和约束，各组独立重置。结果与原批次分开。

| 组别 | 记录结果 | 动作数 | 调用数 | 评测函数秒数 |
|---|---|---:|---:|---:|
| N | RGB 缺失后 skill 异常 | 3 | 1 | 24.19 |
| H0 | RGB 缺失后 skill 异常 | 3 | 1 | 25.25 |
| H1 | 成功，原生评分 100 | 113 | 2 | 87.80 |

N/H0 都到达注入点并因 skill 异常结束。H1 在向工作进程转发前观察到缺失，确认停止、重新采集 RGB，再由新原生工作进程执行模型选择的重启。两次请求共用一个 Session；审计核对一次替换、113 次动作派发及原生评分 100。这确认了局部恢复结果。目录只有一个可选 skill，尚未证明 LLM 推理、历史或长程规划的贡献；仍需要规则恢复对照及设计中的消融。

## 验收条件

| 条件 | 结论 | 缺少的证据 |
|---|---|---|
| G1 | 证据不足 | 基础集每组只有一个 case；缺少功效设计、保留集配对非劣分析及逐任务族覆盖。 |
| G2 | 证据不足 | 缺少原生终止时间戳、受控预热、资源峰值及配对时延/费用区间。 |
| G3 | 证据不足 | 缺少 L 集、目标移动及抓取失败覆盖，以及双任务族优效实验和消融。 |
| G4 | 局部检查通过，正式覆盖不足 | 三条成功 H1 轨迹通过顺序、摘要与绑定审计；尚无完整 S/L/U/X 覆盖及更广策略的停止保证。 |

记录的评测函数耗时包含 skill 冷启动及各路径自身的收尾，不是正式任务完成时延。失败在描述性截断评测耗时中使用共同期限，不能把提前失败视为提速。两个独立保留批次共 13 次请求、54,533 token；按固定公开峰时单价并计入缓存命中，规范化折算约 0.009360084 美元，不是实际账单或 G2 结论。缓存状态与组顺序尚未按正式费用对照控制。单价见 [DeepSeek 价格](https://api-docs.deepseek.com/quick_start/pricing/)。

## 证据与复核

[证据索引](evidence.json)固定了 51,692,355 字节的压缩包及其清单，842 个文件均通过本地 SHA-256 核验。包内保留模型请求/响应、Session、停止/提交/绑定/动作记录、原生结果、故障、源码版本记录、配置及审计源码，不含 API key。[原批次摘要](paired-pilot-01.json)与[独立诊断摘要](paired-pilot-02-vision.json)保留所有分配 episode；完整诊断留在证据包中。

操作者在隔离部署产物目录下保留 `acceptance-2026-10-21/evidence.tar.gz`。取得并校验该包后，可用已安装的适配器重新生成各批次的描述性报告：

```sh
python python/embodied/scripts/paired_pilot_report.py /absolute/path/to/paired-pilot-01
python python/embodied/scripts/paired_pilot_report.py /absolute/path/to/paired-pilot-02-vision
```

## 正式验收前必须完成的工作

1. T0/T7：选择并冻结最强可用同模型原生配置、支持范围及共同重试/预算规则，完成 H0 等价及基础对照。
2. T8–T13：实现多子目标执行及可观测完成、目标移动/抓取失败检测、相应停止提供方及独立核验的 L/U/X case；确认新增策略路由可用。
3. T12/T14：补齐原生终止计时、资源/费用计量、H1-R/H1-M 及规则恢复参照；使用独立预实验进行区间校准及至少 90% 的功效设计。
4. T14/T15：预登记独立保留场景、随机化配对顺序、样本数及基础设施故障规则，完整执行 G1–G4 联合验收，不修改阈值或挑选成功重跑。
