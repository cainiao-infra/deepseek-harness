# 渲染恢复与真实任务验证

[English](renderer-restoration.md) | 中文

## 修复与范围

渲染器空首帧问题已修复，增量 A 剩余的六项原生物理任务验证已完成。已安装的 Isaac Sim 无法在动态库搜索路径中找到 `libGLU.so.1`，导致 `libneuray.so` 和 RTX 渲染器初始化失败，随后 annotator 返回空 CPU 数组。为仿真进程补齐主机上已有的隔离库目录后，同一固定拾取场景恢复三路 RGB 和 200 个真实动作；客户端日志不再出现渲染器错误。共享系统及已安装 Python 环境未修改。

`simulation_library_dirs` 将显式配置的现有绝对目录前置到仿真进程的 `LD_LIBRARY_PATH`。目录无效时在启动前失败，策略进程环境不受该配置影响。[动态库记录](restored-graphics-runtime.json)保留 GLU 实际路径、文件摘要和依赖解析结果；[部署记录](deployment.json)保留需要复用的库目录。空帧保护继续保留，避免缺失图像进入复制内核。

## 物理结果

下表来自一个原配置 pi05 对照和六个预先分配的修复后原生 N 试验。六个试验覆盖 pi05 与 sparse-memory 各三个固定开发任务。全部获得三路 480×640 RGB 首帧，并完成独立评测、进程退出和清理；规划尝试均为零。任务结果与动作生成分别记录。

| 策略 | 任务 | 实际动作数 | 原生任务判定 |
|---|---|---|---|
| pi05 (原配置对照) | general_pickup | 200 | 失败 |
| pi05 | general_pickup | 200 | 失败 |
| pi05 | stack_blocks_by_language | 400 | 失败 |
| pi05 | store_tools_in_toolbox | 900 | 失败 |
| sparse-memory | general_pickup | 76 | 成功 |
| sparse-memory | stack_blocks_by_language | 400 | 失败 |
| sparse-memory | store_tools_in_toolbox | 900 | 失败 |

[机器可读结果](restored-summary.json)关联每个能力描述、manifest、原始绑定、首帧、计时、终止和覆盖报告。Sparse-memory 的拾取在 76 个动作后成功，原生成功终止时间为 22.38 秒，首次动作约 13.52 秒；这些时间包含策略冷启动，不是未插桩性能对比。覆盖仅验证该固定开发场景的 `task-complete`，样本数为 1，不推广为整个拾取任务族或中间子目标能力。

其余修复后任务没有成功，继续标记为未验证。pi05 变换修正没有在这三个案例中产生任务成功，稀疏记忆的堆叠和工具箱同样未通过。工具箱程序此前声明的不支持效果保持不支持。执行验证已完成，能力覆盖目标尚未全通过；后续恢复逻辑只能使用实际覆盖范围。正式留出运行数仍为零，G1–G4 未验收。

## 测试与可复核证据

[归档回执](restored-archive.json)记录本地、远端位置和 SHA-256。归档保留全部七个试验的原始日志、观测、实际输入输出变换、动作、目录与计划，修复后适配器源码、实际加载策略源码、依赖版本，以及检查点清单。先前 22 个失败或未执行分配及其归档继续保留，未被本轮结果覆盖。所有实验进程停止后才冻结归档。

测试校验库目录配置、父环境隔离及错误拒绝，并从全部七份原始记录重算覆盖报告；六个冻结分配必须完整保留，不能删除失败。[验证回执](restored-validation.json)记录执行过的测试和文档检查。原始归档的全部成员逐项校验摘要；原生完整任务成功仅支持 `task-complete`。
